# Wiki export of the in-game help (inc-k2le)

**Goal.** Publish the in-game help encyclopedia to the GitHub Wiki of
`networkingguru/incursion-roguelike`, one page per entry, generated by the
game's own help code and updated on every push.

**Architecture.** A new command-line mode, `incursion-headless -wikihelp <dir>`,
loads the modules and writes Markdown pages into `<dir>`, then exits. It takes
its text from the same functions the in-game help calls, so the wiki cannot
drift from the game. A Python validator checks the output. A shell script
publishes it to the wiki repository; the pre-push hook starts that script.

**Precedent.** `-resorder` (src/Wposix.cpp:591, 640; src/SaveV1.cpp
`RunResourceOrder`) is a mode of the same shape: parse the flag, load modules,
print, exit. `tools/resource_order_check.py` runs it directly. Follow it.

**Upstream exporter.** `Game::WriteHTMLHelp()` (src/Help.cpp:2104) writes 22
topics, one HTML file each. It works in this port (run 2026-10-04: 22 files,
no errors). Its character switch (src/Help.cpp:2185-2240) is the reference for
what each colour code and markup character means. Do not change it.

## 1. Pages

Every page is a `.md` file. GitHub renders inline HTML in it, so the body MAY
use `<b>`, `<br>` and `&nbsp;`.

**Prose chapters**, one page each, text from `TextTerm::GetHelp(s, "help::<topic>")`:
mainmenu (page `Home`), intro, chargen, commands, interface, adventuring,
combat, magic, overland, OGL.

**Entry pages**, one per entry, built from the same per-entry source the
help-mode menus use (src/Help.cpp, the `OPT_HELP_MODE` branches):

| Kind | Entries | Page text |
|---|---|---|
| Race | every race in every module (`m->RaceID(i)`), core and subrace | `DESC(id)` |
| Class | every class without `CF_PSEUDO` | `DESC(id)` |
| God | every god (`m->GodID`) | `DESC(id)`, then a line linking each of its domains |
| Domain | every domain, as `HelpDomains` enumerates them | `TDOM(id)->Describe(true)` |
| Feat | `FT_FIRST..FT_LAST`, skipping `FeatUnimplemented` | `DescribeFeat(i)` |
| Skill | `1..SK_LAST-1` | `DescribeSkill(i)` |
| Spell | every effect `HelpSpells`, `HelpWizSpells`, `HelpOtherSpells` or `HelpPowers` lists, with the same filters | `TEffect::Describe(NULL)` |

A spell on several lists gets ONE page; each list links to it.

**Index pages**, one per kind: `Races`, `Classes`, `Gods`, `Domains`,
`Feats`, `Skills`, `Arcane Spells`, `Divine Spells`, `Druid Spells`,
`Other Spells`, `Powers`, `Spell Index`. Each lists links to its entries,
grouped and ordered as the matching help topic groups them (spells by level,
arcane also by school; races core then subraces; classes core then prestige).
The prose before the list in the help topic (for example `help::feats`'s
introduction) goes at the top of its index page.

**`_Sidebar.md`** links `Home`, the prose chapters and every index page.

**Page names.** The page name is the entry's display name. When two entries of
different kinds share a name, BOTH get the suffix ` (<Kind>)`. The file name
is the page name with spaces turned to `-` and any character outside
`[A-Za-z0-9()'+,._-]` removed. Two entries MUST NOT map to one file name; the
mode fails (exit nonzero) if they would.

**Output is deterministic.** Same source, same bytes: sorted order, no dates,
no build stamps. An unchanged game produces no wiki commit.

## 2. Converting the help text

One converter, used for every page, mapping the game's text as
`WriteHTMLHelp` does, with these corrections:
- A bright colour opens `<b>`; any other colour closes it. Bold MUST be
  balanced: never a `</b>` with none open, never an open `<b>` at a line end.
- `\n` ends a line with `<br>`; a blank line ends a paragraph.
- A run of two or more spaces, a leading space, and `_` become `&nbsp;`.
  `~` becomes `%`.
- `<`, `>` and `&` in the text become `&lt;`, `&gt;`, `&amp;`. Markdown
  specials that would change meaning (`*`, `#`, `|`, `` ` `` at a line start,
  `[`, `]`) are backslash-escaped.
- `{XX}` (an in-topic jump anchor) is removed. `{XX:topic}` becomes a wiki
  link `[[<page>]]` to that topic's page.
- `-SHADOW` text is dropped, as in the HTML exporter.

## 3. Validator — `tools/check_wiki.py <dir>`

Fails (exit 1, one line per fault) when:
- an index page lists no entries;
- a `[[link]]` names a page with no file;
- an entry page has an empty body;
- `Home.md` or `_Sidebar.md` is missing.
`--selftest` builds broken fixtures in a temp dir (an empty index, a dangling
link, an empty page, a missing sidebar) and asserts each one fails, then a
good fixture passes. A run with no argument generates into a temp dir with
`./incursion-headless -wikihelp` and checks that.

## 4. Publishing — `tools/publish_wiki.sh`

1. Build `BACKEND=posix OUT=incursion-wiki ./build_macos.sh` (its own binary,
   so it never races the gate's `incursion-headless`).
2. Generate into a temp dir; run `tools/check_wiki.py` on it; stop on failure.
3. Keep a clone of `https://github.com/networkingguru/incursion-roguelike.wiki.git`
   at `~/Scripts/incursion-roguelike.wiki`; clone it if absent; `git pull --ff-only`.
4. Replace its `.md` files with the generated set (delete pages that are no
   longer generated); commit only if `git status --porcelain` is non-empty,
   message `Regenerate from <main repo short hash>`; push.
5. Log to `logs/wiki-publish.log`. Exit 0 with a message when the wiki
   repository does not exist yet (GitHub creates it on the first browser save).

`.beads/hooks/pre-push` starts it in the background after the
`tools/sync_issues.sh` call, detached (`nohup ... &`), so a push is never
delayed or blocked. `INCURSION_NO_WIKI=1` skips it.

## 5. Rule

`.claude/rules/publishing.md` and `AGENTS.md` (Publishing anything
outward-facing) gain a second exemption: wiki pages that
`tools/publish_wiki.sh` generates verbatim from the game's help need no
pre-read. Hand-written wiki pages still do.

## Out of scope

Monster and item pages (they need a ruling on what a page may reveal). Linking
entry names inside body text. Any change to the in-game help or to
`WriteHTMLHelp`.
